公开接口核实结果

基础版本：PowerContext 1.5.1（PyPI 发布版），运行 powercontext server run + SQLite 持久化。

  • POST /v1/scopes：同一 idempotency_key 复用同一 Scope，返回真实 scp_… 标识
  • POST /v1/memory/remember：写入原子记忆，返回 atomic-memory/art_…@1 与 changed
  • POST /v1/atomic-memory/list：按 kind 与 states 分页读回，含 state_version
  • POST /v1/memory/search：未配置嵌入模型时 mode=text，仅全文检索，如实展示
  • POST /v1/context/prepare：返回 powercontext.prepared-context.v1 有界内容与字节数
  • POST /v1/atomic-memory/lifecycle：以 state_version 乐观并发把条目置为 forgotten
  • POST /v1/sources/content：答题流水作为证据留存，返回 content/<source_id>
  • 写入失败：超长文本被服务端以 422 invalid_request 拒绝，客户端保留真实 X-PowerContext-Request-Id

完整契约留档：reference/powercontext-1.5.1-openapi.json（由运行中的服务 GET /openapi.json 下载）。

自动化验收覆盖

  • 跨会话持久性：写入后用全新应用实例重新读取同一 Scope
  • 服务重启持久性：停止并重启 PowerContext 后按记忆续接复习（见 RUNBOOK 第 5 步）
  • 记忆驱动选题：复习首题必须落在记忆中的薄弱知识点，且携带记忆标识
  • 不同身份隔离：两个 Scope 的记忆、检索与选题互不可见（数据层面，非权限层面）
  • 写入失败：服务不可达返回 503 powercontext_unavailable，且不留下任何“已保存”假状态
  • 重复提交保护：同一会话二次提交由服务端持久回放当时的判分与回执，答题流水与记忆都不增加
  • 部分写入如实提示：批量写入中断时返回已写入条目的真实回执，重试只补齐缺失条目
  • 遗忘与撤回：forgotten 条目退出召回，历史仍可核验
  • 可导出记录：JSON / Markdown 均含真实记忆标识与答题流水

复现命令：scripts/acceptance.sh（真实服务 + 真实重启 + pytest），输出留档于 evidence/。

能力边界与不做的事

本作品做到

  • 核心闭环不依赖模型 API：判分、选题、记忆读写全部可离线复现
  • 记忆真的影响安排：复习顺序由读回的掌握度、连错次数与偏好计算得出
  • 每条依据可追溯：显示 atomic-memory/art_…@修订号 与操作留痕
  • 按身份分 Scope 的数据隔离与撤回：支持按条遗忘与一键清空

本作品没有做

  • 不使用动态 AI 出题：24 道题全部为原创内置固定题库
  • 未配置推理模型时不做语义向量检索，也不假装自动抽取记忆
  • 不虚构用户数、使用次数、提效百分比或他人反馈
  • 不在演示身份中存放真实个人信息；显示名不写入 PowerContext
  • 没有登录与授权：身份标识只是本机选择 Scope 的短名，不是凭证。同一台机器（或同一个可达端口） 上知道标识的人就能读写同一份记忆，因此本项目只适用于本机或受信任内网， 公开多用户部署需要先引入认证并把 Scope 绑定到认证主体（见 RUNBOOK 第 8 步）。
  • 不宣称“身份隔离 = 权限隔离”：验收证明的是不同标识落在不同 Scope、数据互相读不到
